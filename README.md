# DeadBot v0.8.0

## 日报、六维建议与详情补全

- `/日报 [群友称呼或全部] [今天、昨天或YYYY-MM-DD]`，别名 `/每日总结`：默认全名单。按中国时间的比赛结束日期选取本地标准、排位比赛，比赛去重，个人胜负分模式；展示自己的当日最佳一局和最多两项成就，不对新手与老玩家做低分排名。
- `/建议 [群友称呼] [标准或排位或全部]`，别名 `/打法建议`：不指定群友时使用发送者绑定，支持 `/建议 排位`。展示输出、发育、承伤、辅助、前期、推进；发育仅使用来源2、3的兵野灵魂，不用最终灵魂冒充farm；缺失字段不补零，控制时间不臆测。
- `/补全 [群友称呼或全部]`，别名 `/补全详情`：每位群友标准、排位分别选最近50场，合并比赛ID，只抓缺失详情，每轮最多25场，至少5秒请求间隔。同步历史后自动执行同样补全。404延迟1小时再试，其他错误延迟1分钟；401/403/429停止本轮。仅查询公开已有详情，disable_steam=true，不触发回源。

个人六维是打法观察，不改变原有MVP算法或成就门槛。六维指数以自己的最近10场对比此前40场：各项先匹配同英雄、同模式；此前同英雄至少5场，近期至少5场可比较才显示。单项使用个人比值中位数；输出伤害/击杀80:20、发育兵野收入100、承伤实际伤害/减免/吸收70:20:10、辅助助攻/队友治疗/护盾/阻止治疗60:20:10、前期伤害/助攻70:30、推进建筑伤害/清兵80:20。比值经log2转换到指数50基准，范围0～100；主要字段缺失或基准为0时不生成该轴指数。高发育与高承伤只描述活动量，不能解释为好坏。前期边界沿用20分钟附近快照，缺失则不展示。

建议每个模式最多两条，明确可核实的数据变化和复盘方向，不把数据相关性当成走位、出装、意识或玩家意图的证明。没有可比历史时仅给练习提示和实际六维数据。所有建议与日报本地生成，不调用Gemini等AI API；六维缓存随历史与详情内容自动失效。日报目前是指令查询版，不新增定时群发或开黑统计。

适用于 AstrBot 的 Deadlock 群友战报插件。使用免费 Deadlock API，无需 StatLocker API Key；旧密钥配置保留但不发送。全场12人用于贡献比较基准，仅展示名单内群友；兵野灵魂效率仍在同队比较。

## 指令

- `/帮助` = `/指令` = `/deadbot帮助` = `/deadbothelp`：手机端短版帮助，每行一条指令与简短用途；`/帮助 详细` 查看完整用法与同义词，其他帮助别名也支持「详细」。AstrBot及其他插件指令使用原有 `/help`。
- `/成就详情 比赛ID [刷新]` = `/成就 比赛ID [刷新]`：本局全部个人成就，复用本地详情和原战报查询流程。
- `/成就规则 [类别或成就名称]`：全部成就条件和启用状态；支持史诗、稀有、少见、常见、整活以及确切名称。
- `/战报 比赛ID`：基础数据、五维贡献得分、群友 MVP／最低分、趣味统计。
- `/评分详情 比赛ID`：保留兼容，使用与战报相同的完整原始数据布局。
- `/评分规则`：查看当前规则。
- `/战报 比赛ID 刷新`：跳过本地缓存，重新请求已收录详情；用于数据库更新有延迟的比赛。
- `/战报 StatLocker单局链接`：支持单局链接。
- `/群友名单`：配置中的完整名单；别名 `/名单`、`/群有名单`、`/查看群友名单`。
- `/同步` = `/同步历史` = `/刷新`：同步接口已收录的历史列表，默认全部群友；也可 `/同步 群友称呼`。
- `/绑定 群友称呼`：绑定发送者与名单中的游戏账号，同一机器人和同一平台用户标识下复用。重复绑定更新自己的选择。
- `/最新` = `/最新数据` = `/最新比赛`：从本地历史或已查询记录中选出自己最新参与的一局，再发送战报；没有详情时仍使用原战报查询流程。也可 `/最新 群友称呼` 指定群友。
- `/分析` = `/打法分析`：默认分析自己。标准比赛、排位分别取最近50场，排除乱斗、其他模式、未知胜负和弃赛。支持 `/分析 排位`、`/分析 群友称呼`、`/分析 群友称呼 标准`。
- `/英雄统计 群友称呼 [英雄或全部] [天数，0为全部] [游戏模式ID或全部]`。
- `/群友画像 群友称呼`：本地历史总数和最近比赛，不推断长期进步。

群内先真正 @机器人；私聊直接发送指令。名单在 WebUI → 插件 → DeadBot → 配置修改，格式 `Account ID=称呼`，不要填写 SteamID64。

“分析”使用本地数据和按数据指纹自动失效的统计缓存，不请求 API。统计胜率、最近10场对比此前10场的走势、场均K/D/A、综合KDA、常用英雄、伤害、承伤、建筑伤害、参团率、命中率、爆头率和灵魂/分钟。命中率为总命中/总射击，爆头率为总爆头/总命中；未知字段不按0处理，详情不足时显示该指标实际场数。只有前后10场均有完整射击统计时才展示命中率变化；分析不能据此推断个人所有历史或稳定实力变化。

`/刷新` 单独使用是历史同步；`/战报 比赛ID 刷新` 仍是更新该局详情，两个用法分开解析。

## 本地化成就

采用用户确认的56项名称；38项已启用，18项保留规则但等待可靠数据。同系列只显示最高档，按史诗、稀有、少见、常见、整活排序。反补王和振刀王继续按名单群友相对排名，放入对应玩家的本场成就行；与固定门槛成就合计最多展示3项，完整结果可用 `/成就详情` 查看，均不参与MVP计分。

直接使用击杀、死亡、助攻、最终灵魂、对英雄伤害、建筑伤害、实际承伤、队友治疗、阻止治疗、成功/失败招架和对英雄射击统计。灵魂/分钟是最终灵魂积累速度，不能解释成兵野farm；治疗系列明确只统计队友治疗。命中率系列要求对英雄射击至少100次；爆头率系列还要求命中至少30次，爆头率按爆头/命中计算。助攻和死亡的倍数门槛允许击杀为0，但仍要求相应绝对次数。缺字段、无效时长或不符合完整标准/排位评分条件时不发个人成就；未知值不视为0。

尚未启用：类别评级系列、吸收伤害系列、刷了送、连杀和前后半场击杀系列、控制评分、一招鲜吃遍天、兵线反补。现有MVP分项不等同类别百分位；API吸收字段不直接代替截图吸收口径；不使用时间快照猜完整击杀顺序。整活称号不推断玩家意图，也不扣分。

成就查询从现有原始比赛和射击统计即时计算，不改评分版本或历史数据库。旧缓存比赛也能获得新成就；无需重新同步历史或请求API。

## MVP 计算与展示

战报只在开头显示比赛结果，个人标题显示“评分：70.0/A”；不展示括号注释、权重、换算或技术说明。等级仅为展示：90起S、80起A+、70起A、60起B、50起C、40起D、低于40为E，不影响实际分数。

战报使用 Emoji 分区：顶部显示时长、结果、MVP和最低分；反补王、振刀王放入个人成就。每位群友合并展示击杀参与、伤害、射击、承伤和推进。治疗、队友护盾、阻止治疗、减免和吸收仅展示正值。振刀王按成功招架次数比较，缺任何群友计数时不评选，已知并列则全部展示。QQ 使用纯文本，WebUI ChatUI 使用 Markdown 加粗；两种排版使用相同评分数据。

|维度|小项权重|
|---|---|
|前期18|前20分钟英雄伤害12、前20分钟助攻6|
|输出32|20分钟后英雄伤害12、整场击杀20|
|推进15|总建筑伤害12、清兵3|
|承伤15|实际英雄承伤10、减免3、吸收2|
|辅助20|后期助攻10、队友治疗4、队友护盾3、阻止治疗3|

每个小项相对全场12人平均值计算：`参照权重×0.6×个人数据/全场均值`，单项不封顶，最终总分限制0～100。权重是参照份额而非分项硬上限。全场零值或一人缺字段时统一排除该小项；权重先同维度再全局按比例分配。缺失超过25分权重或核心伤害／助攻／结算击杀不完整时不评分。小兵仅解释为清兵，建筑暂不按基地内外拆分。

治疗、队友护盾、阻止治疗额外乘 `个人数据/(个人数据+每分钟量级×比赛分钟)`，每分钟量级依次50、20、50；避免全场仅一人有少量该数据时相对均值给出过高分。

每次死亡成本 `135×sqrt(复活等待秒数/8)`，按所有死亡累加为C。D为比赛内复活等待时间合计，末次死亡窗口截至比赛结束；不把结束后的时间计入D。死亡扣分 `min(25,40×D/比赛秒数+5×C/全场平均C×贡献系数)`，全场无死亡时成本项为0；贡献系数 `sqrt(全场平均基础分/max(个人基础分,1))` 限制0.75～1.5。死亡明细不完整不评分；API结算死亡数与快照不同、但明细匹配其中一份计数时保留结果并标记。

兵野经济效率奖励0～5：兵线来源2＋野怪来源3的 `gold+gold_orbs`，占同队同类灵魂总量的比例；贡献占比取个人基础分/同队基础分合计。基础分达到队伍均值且兵野占比小于贡献占比时，奖励 `5×max(0,1-兵野占比/贡献占比)`。不是全部farm来源，不直接用最终灵魂作farm。来源缺失时全队不计算奖励。

先累计全场每人的原始贡献 `P=基础分-死亡扣分+经济奖励`，保留负值和超100值用于比较，再算 `z=(P-全场平均P)/max(12,全场总体标准差)`。映射分 `50+25*z`；超过90时使用 `90+10*(1-exp(-(映射分-90)/10))`，最终限制0～100。标准差下限12避免接近同分时放大细微差异；均等贡献得50分。此映射是本地候选规则，不声称复刻StatLocker，3场8个已知评分样本仅用于校准而非独立验证。

雷达五维和死亡/经济调整展示原始贡献，总评分展示标准化结果，两者不直接相加。相对原始贡献，单调映射保持先后顺序，0分以下可能并列；高分尾部压缩减少完美分。只在同队名单群友间评选；只有一位群友或显示分数相同不区分。最低分不代表输局责任，不给路人排榜。

评分缓存升级到 `deadbot-contribution-v3`，按原始比赛数据重新计算；旧版本保留供对比，不混用旧分数，无需重新请求API。

## 数据边界

只对标准比赛/排位评分：`game_mode=1,match_mode=1或4`。乱斗、私人、机器人、队伍不足完整6v6、标记不计分仅展示数据；任何玩家弃赛或核心数据不足时无法形成全场比较基准，不评分。

优先全场20分钟共同快照，允许前后120秒内共同快照，实际分界及诊断保存在评分缓存中；无可用分界不评分。结束快照允许最多落后120秒。比赛不超过20分钟时，后期伤害12转前期伤害，后期助攻10转前期助攻，整场击杀项保留。

反补、成功/失败招架、对英雄命中率/爆头率、击杀参与率仅趣味展示，不改变MVP。自定义统计按接口提供的名称映射ID，缺字段不视为0；成功率须完整的成功/失败统计。控制秒数、有效推线、带节奏、灵瓮个人贡献未核实，不计入评分。

## 本地保存与网络

数据库 `data/plugin_data/astrbot_plugin_deadbot/history.sqlite3`：保留历史与旧StatLocker表；完整详情使用现有 `match_detail_cache`，评分结果独立放在 `match_score_cache`，按比赛ID、评分版本及原始数据指纹复用，名单改动即时生效。

查询优先本地详情，命中时不请求API；新成功查询保存完整详情和名单群友规范化记录。网络接口 `/v1/matches/{id}/metadata?disable_steam=true`，不触发Steam回源；超时25秒、网络请求间隔5秒、429冷却60秒。历史同步每账号10分钟冷却。长战报分段发送。

战报评分、日报和个人建议均不需要LLM调用；个人变化须满足同英雄样本门槛。目前不含定时主动推送或AI评论。
