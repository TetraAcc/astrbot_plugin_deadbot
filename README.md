# DeadBot 个人复盘

适用于 AstrBot 的 Deadlock 战报插件，支持原站评分查询、群友历史、个人分析与基础日报。

历史数据使用公开 Deadlock API；评分使用 StatLocker 网页，无需 StatLocker API Key。网页尚未收录或抓取失败时明确报错，不使用本地评分替代。

当前版本：**v0.9.5**。版本记录见 [更新日志](CHANGELOG.md)。

## 快速开始

1. 安装插件，群友名单可以留空，无需 API Key。
2. 发送 `/绑定 AccountID`，或 `/绑定 https://steamcommunity.com/profiles/你的SteamID64/`；也支持直接填写 SteamID64 和 SteamID3。
3. 发送 `/最新`，插件按需刷新本人的比赛历史并返回个人战报。
4. 使用 `/分析`、`/建议` 查看已积累的数据；详情不足时会提示样本不足。

绑定是查询偏好，不验证 Steam 账号归属。暂不解析 `/id/自定义名` 链接。使用 `/解绑` 可解除当前身份的绑定，不删除共享比赛数据。

群聊和私聊使用相同指令。绑定按平台实例和发送者标识保存；如果 QQ 为不同场景提供不同标识，需分别绑定，不按昵称猜测身份。已有绑定继续有效，即使该玩家不在名单中。

`/最新` 只更新目标玩家：2 分钟内复用历史缓存，同一玩家同时查询合并为一次历史请求；历史接口最多 3 个并发、30 个待处理任务。限流或刷新失败会说明使用本地记录。最新指接口已收录的比赛，不代表进行中的比赛或刚结束尚未入库的比赛。

战报直接读取 StatLocker 网页的原始评分、评级、全场排名及贡献分项，自研评分已暂停。直接 `/战报 比赛ID` 展示已绑定账号；StatLocker 完整链接可指定查询账号。采集整场12人作为背景，输出查询对象。首次安装请完成 [浏览器采集配置](STATLOCKER_SETUP.md)。

群聊中按机器人的唤醒设置使用指令，通常需要先 @机器人；私聊可直接发送。

## 可选群友名单

名单仅用于称呼、旧版群体查询与批量同步，可留空。当前名单在同一插件配置内共享，尚未实现独立按群管理；不要把它当成群成员权限或身份验证。

名单每行填写一位群友：

```text
12345678=小明
87654321=小红
```

左侧填写游戏 **Account ID**，右侧填写群友称呼。示例编号需替换为真实账号编号。

### Account ID 是什么

Account ID 是 Steam 账号的短数字编号（32 位无符号整数，以十进制数字填写），用来识别对应的 Deadlock 玩家，也是 SteamID3 `[U:1:数字]` 中的最后一段。

它不是游戏昵称、Steam 登录名、自定义主页名，也不是17位的 SteamID64。填写时只填写数字，不带 `[U:1:...]` 外壳。

获取与换算方式：

- 如果 SteamID3 为 `[U:1:12345678]`，填写 `12345678`。
- 如果只有普通个人账号的 SteamID64，可按 `Account ID = SteamID64 - 76561197960265728` 换算。例如 `76561197972611406` 对应 `12345678`。请使用支持大整数精确计算的工具，不要用截取末尾数字的方式转换。
- Steam 数字主页链接 `/profiles/` 后通常是 SteamID64；StatLocker 玩家主页 `/profile/` 后的数字也应先确认类型，不要直接当作 Account ID 填入。自定义主页名不能用上述公式换算。

关于 SteamID 的组成，可参考 [Valve SDK 的账号编号定义](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/public/steam/steamclientpublic.h)；查找 SteamID64 可参考 [Steam 支持说明](https://help.steampowered.com/en/faqs/view/2816-BE67-5B69-0FEC)。

配置好 `12345678=小明` 后，可使用 `/绑定 小明`、`/最新 小明` 等指令。

名单通过 WebUI 修改，修改后保存并重载插件。发送 `/群友名单` 可检查当前配置。

## 比赛战报

| 指令 | 用途 |
| --- | --- |
| `/战报 比赛ID` | 查看查询对象的 StatLocker 评分、评级与贡献明细 |
| `/战报 比赛ID 刷新` | 重新获取该局比赛数据 |
| `/最新` | 按需刷新并查看自己的最近已收录比赛 |
| `/最新 群友称呼` | 查看指定群友的最新一局 |
| `/评分规则` | 查看贡献评分说明 |

`/战报` 也支持 StatLocker 单局链接。`/评分详情` 保留为 `/战报` 的旧命令兼容别名，参数和输出完全相同，不提供额外的详细页面。

这两个入口只接受比赛 ID（或链接）以及可选的 `刷新`，多余参数会提示用法，不会切换为成就模式。查看成就请使用 `/成就`。

评分缓存24小时，手动刷新可重新抓取。同场并发请求合并，不同场串行处理，最多8场正在处理或等待，场间至少3秒。抓取失败后该场冷却60秒。刷新失败明确提示失败，不返回旧分数充当刷新结果。

## 绑定与数据更新

| 指令 | 用途 | 权限 |
| --- | --- | --- |
| `/绑定 群友称呼` | 将自己的聊天账号绑定到名单中的游戏账号 | 普通用户 |
| `/群友名单` | 查看当前名单及 Account ID | 普通用户 |
| `/同步` | 更新全部名单群友的比赛历史 | 管理员 |
| `/同步 群友称呼` | 更新指定群友的历史 | 管理员 |
| `/补全` | 补抓近期缺失的比赛详情 | 管理员 |
| `/补全 群友称呼` | 补抓指定群友的比赛详情 | 管理员 |

同步历史后会自动检查并补抓近期缺失的详情，每轮最多处理25场。已有详情会复用，尚未完成的部分可稍后继续 `/补全`。

`/最新`、`/分析`、`/建议` 不指定群友时，使用自己的绑定账号；也可以直接指定名单中的群友称呼或 Account ID。

## 分析与建议

| 指令 | 用途 |
| --- | --- |
| `/分析` | 查看自己的近期表现 |
| `/分析 排位` | 只分析自己的排位比赛 |
| `/分析 群友称呼 标准` | 分析指定群友的标准比赛 |
| `/建议` | 查看自己的六维观察与练习方向 |
| `/建议 群友称呼 排位` | 查看指定群友的排位建议 |
| `/英雄统计 群友称呼` | 查看英雄使用情况和胜率 |
| `/群友画像 群友称呼` | 查看本地历史数量与最近比赛 |

分析按标准和排位分别选取最近50场有效比赛。

建议包含输出、发育、承伤、辅助、前期、推进六个方面，结合自己的同英雄、同模式历史进行观察。可比较的数据不足时，会说明限制。

英雄统计支持进一步筛选：

```text
/英雄统计 群友称呼 英雄名或全部 天数 游戏模式ID或全部
```

例如，查询某位群友最近30天、全部英雄和模式的记录：

```text
/英雄统计 小明 全部 30 全部
```

天数填写 `0` 表示查询全部本地历史。默认游戏模式 ID 为 `1`，填写 `全部` 表示不限制模式。

分析与建议均基于本地数据生成。

## 每日总结

```text
/日报
/日报 昨天
/日报 小明 昨天
/日报 全部 2026-10-28
```

默认查看今天全部名单群友的总结，按北京时间的比赛结束日期统计，标准和排位分别展示。

日报仅汇总本地已收录比赛的基础数据与胜负，不再使用自研评分挑选最佳一局或评定成就。使用前可先同步历史并补全详情。

## 数据说明

- 评分优先使用独立网页缓存，刷新指定比赛时重新采集 StatLocker 页面。
- 公开接口可能存在收录延迟；新比赛暂时查不到时，可稍后重试。
- 本地统计反映已收录的数据，详情不足会影响可展示的指标。
- 数据库保存在 `data/plugin_data/astrbot_plugin_deadbot/history.sqlite3`。

## 常见问题

**提示尚未绑定账号怎么办？**

发送 `/绑定 群友称呼`，称呼须与配置名单一致。

**最新比赛没有更新怎么办？**

请管理员先 `/同步 群友称呼`；缺少详情时再使用 `/补全 群友称呼`。

**有比赛数据，但没有评分或建议怎么办？**

评分依赖 StatLocker 页面可访问且完整；补全 Deadlock API 详情不会生成原站评分。建议仍依赖历史数据。

**接口提示限流或超时怎么办？**

等待冷却结束后重试，已有本地数据会保留。

## 本地验证

在安装了 AstrBot 的 Python 环境中，于插件目录运行：

```sh
python -m unittest discover -s tests -v
```

测试使用 AstrBot 的真实内容模型验证临时上下文不会保存到历史，并检查名单变更、无效配置、成就展示和 Account ID 示例。

命令测试在独立子进程及临时 `ASTRBOT_ROOT` 下保留实际处理器和装饰器，使用真实 AstrBot 命令注册器及过滤器验证别名和参数解析；隔离插件构造函数、模拟网络和历史库。此验证不等同于平台唤醒、完整消息调度或实机集成验证，合并前仍需重载并人工检查命令。

评分测试只依赖 Python 标准库，可单独运行：

```sh
python -m unittest discover -s tests -p 'test_scoring.py' -v
```

测试使用自行构造的匿名比赛数据，不请求真实比赛接口、不读取真实聊天配置、不操作真实 SQLite 数据库。评分测试验证模型边界和数据保护规则；不代表真实比赛准确率验证。

真实比赛验证及局限见 [129078319 对照](MATCH_129078319_REVIEW.md)。所有自研评分已退出在线战报；旧模型及对照文档仅保留作历史研究。
